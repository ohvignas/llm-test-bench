# Mastra implementation plan

**Goal:** Use one tool-enabled Mastra agent per prompt/model while preserving the authenticated comparison application.
**Architecture:** Trusted Node controller, isolated Docker workers, authenticated Python provider bridge and durable SQLite checkpoints.
**Tech stack:** Mastra 1.82.0, OpenRouter AI SDK provider 3.1.0, Node, Flask, Docker, existing Preact UI.
**Spec:** ../specs/2026-11-10-mastra-design.md

- [ ] Runtime: test real Mastra streaming against a simulated provider; implement bounded tools through a Docker adapter; test fixed container options, filename validation, output limits and cancellation.
- [ ] Provider boundary: add scoped tokens, step reservation and confirmed-cost accounting. Test wrong token/model, concurrent callback, exhausted call/money limits and unknown billing without an upstream call.
- [ ] Persistence: store agent events, encrypted source checkpoints and per-step activities. Preserve source and conversation for recovery/chat. Test reload and stop independently of browser readers.
- [ ] UI: default agent mode, visible step/money limits and tool activity; preserve explicit single-call benchmark mode. Count provider steps, not just agent sessions, in comparisons.
- [ ] Delivery: locked dependencies, controller/sandbox images and Compose, documented privilege boundary, CLI diagnostics, full offline tests, Docker smoke tests, idle-state deployment and health verification.
